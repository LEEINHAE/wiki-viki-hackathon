# 구현·검증 기록

기준 명세: [2026-09-21 제품 로드맵](product-roadmap-2026-09-21.md). [P0·P1·P2 항목별 판정](acceptance-matrix.md). 원본의 출발 상태와 완료 표시는 검증 증거로 사용하지 않는다.

## 진행 상태

- 사용자의 개발 보안 완화 요청에 따라 `.env.local`에 `WIKI_CONTENT_POLICY=relaxed`를 적용했다. 일반 사내 정보·실명·직함·연락처·사번·대외비/급여 표현은 업로드를 차단하지 않고 검토 안내로 남긴다. 의미 기반 보안 검사는 생략하고 이 상태를 저장·표시한다. 명백한 인증 키·비밀번호 할당·주민등록번호 패턴은 로컬에서 계속 차단한다. 같은 정책을 원문·파일명·AI 생성/통합/답변·게시·수정·복구에 연결했으며 실패한 업로드는 완화 모드에서 같은 파일로 다시 시도할 수 있다. 운영 빌드는 개발 설정을 무시한다.
- 완화 정책의 실제 HTTP+OpenAI 검증: 합성 이름·직함·사번·이메일과 대외비/급여 표현이 있는 DOCX에서 검토 대기 초안 3개 생성, 이메일 보존, 검사 생략·검토 안내 표시 확인. 합성 비밀번호 할당은 초안 생성 전 차단됐다. [검증 기록](relaxed-policy-verification.json). 엄격한 기본 정책과 완화 모드의 통합/검색 답변 계약, 중요 식별자 차단 회귀를 포함해 `test` 25개 통과·선택 DB 1개 생략, `check` 오류/경고 0, `build` Vercel 패키징 통과.
- 로컬 운영 빌드 미리보기에서도 `WIKI_DEMO_MODE=1`, `WIKI_CONTENT_POLICY=relaxed`를 함께 설정하고 DB·AI 자격 증명은 비운 상태로 확인했다. 실제 서버 응답의 정책은 `strict`, 홈은 로그인으로 303, 업로드 API는 401이었다. 개발 설정이 운영 인증·검사를 우회하지 않음을 확인한 검사이며 실제 Vercel 배포 검증은 아니다. `lint`와 `git diff --check`도 통과했다.

- 사용자 요청으로 로컬 개발 로그인 요구를 비활성화했다. `.env.local`의 `WIKI_DEMO_MODE=1`과 기존 데이터가 있는 5185 서버에 적용했으며 `/login`도 원래 목적지로 바로 이동한다. 기존 세션·계정·문서는 유지한다. 우회 조건은 환경 변수만이 아니라 SvelteKit의 `dev` 플래그를 함께 사용한다. 쿠키 없는 HTTP로 홈·검색·편집·업로드·초안 접근을, 브라우저로 로그인 화면 없이 위키파이어 진입을 확인했다. 최신 `test` 23개 통과·선택 DB 1개 생략, `check` 오류/경고 0, `build` Vercel 패키징 통과.
- 남은 화면 검증을 별도 합성 스키마에서 수행했다. 익명 브라우저의 즐겨찾기·최근 문서·읽기 설정을 추가한 뒤 전체 초기화하여 두 목록의 빈 상태와 글자 크기·폭 기본값 복귀를 확인했다. 예시 초안은 원문 대조 후 Tab으로 검토 확인란에 이동, Space 동의, Tab과 Enter로 게시하여 게시 문서 화면에 도달했다. 검증 전용 서버와 새 스키마는 정리했으며 사용자용 5185 서버·자료는 유지한다. 200% 확대를 위한 네이티브 Chrome 접근은 컴퓨터 제어 권한이 없어 실행되지 않았다.

- 의미별 다중 초안 후속 수정: 현재 UI 미리보기의 비어 있던 AI 설정을 복구하고 같은 스키마·계정·자료를 유지한 채 5185 서버를 재시작했다. 단일 파일을 독립 개념·업무 절차별로 분리하고 같은 개념의 떨어진 내용을 합치도록 프롬프트를 보강했다. AI 미연결 시 업로드 전에 기본 초안 1개만 생성됨을 알린다. 실제 합성 DOCX 하나에서 도서 대여·회의실 예약·신규 구성원 안내 3개 초안 생성, 대여와 반납 단계 통합, 검토 대기 저장을 확인했다. [검증 기록](semantic-splitting-verification.json). Svelte 검사 오류/경고 0, 단위 검사 23개 통과·선택 DB 검사 1개 생략. 기존 네 형식 실AI 검증 스크립트도 다중 주제에서 최소 2개를 요구하도록 강화했으며 전체 네 형식 호출은 이번 수정 후 반복하지 않았다.

- P0 핵심 저장 흐름 구현·격리 DB/HTTP 검증 완료. 전체 화면 접근성과 실제 배포 검증은 진행 중.
- P1 핵심 HTTP 흐름 구현·검증 완료. 검색·요청형 답변·필터/페이지·원문 대조·업로드 재조회/중복 방지·개별 검토 후 선택 게시·태그/출처 보존·두 버전 비교·브라우저 개인화·지도/품질 목록. 실제 AI의 네 형식 생성→수정/게시→답변→상충 통합 HTTP 흐름 통과. 데스크톱 키보드 핵심 흐름 통과, 200% 확대는 미검증.
- P2 주요 기능 구현. 계정·권한·수명 관리·수정 제안·답글·개인화·구독/알림·문서 묶음·이름 변경·게시 문서 병합·전체 상태 복원은 격리 HTTP 검증 통과. 서버 임시 보관·과거 권한 필터·Markdown/메타데이터 내보내기도 검증 통과. 실제 사내 운영 준비 완료가 아니다.

## 구현한 흐름

- 문서 저장·별칭 교체·리비전 기록의 단일 트랜잭션, 정확한 버전 비교, 제목/별칭 충돌 보호. 지운 별칭을 실제 제거하고 기존 URL은 유지한다.
- 휴지통과 복구. ID·별칭·토론·역사를 유지하며 검색에서 삭제 문서를 제외한다.
- 직접 편집·초안 수정·게시·통합·되돌리기의 공통 콘텐츠 검사. 외부 AI 전송 전 정규식 검사, 의미 검사 생략을 통과와 구분한다.
- 편집/게시 공통 렌더러, 모바일 미리보기 탭, 임시 입력 복구(계정은 서버, 익명 개발 데모는 브라우저에 24시간; 인증 정보·승인 체크 제외), 미저장 이동 안내.
- DOCX/텍스트 PDF/XLSX/PPTX, 10MB와 최대 8개 초안. XLSX 시트 순서·빈 열·날짜·저장 수식 결과, PPTX 실제 슬라이드 순서·텍스트 런·줄바꿈·표 텍스트.
- 초안 AI 통합안 생성/재생성/폐기, 새 초안 우선 충돌 목록, 최종 본문 수정과 명시적 적용. 생성은 게시 문서를 바꾸지 않고 적용만 문서·리비전·별칭·초안을 함께 갱신한다.
- 고딕체와 중립 읽기 면, 라이트/다크 토큰, 계층 목차·문단 번호·기존 앵커 호환, 표 스크롤과 각주 복귀, 고정 모달 닫기와 배경 스크롤 잠금.
- SHA-256 적용 이력과 advisory lock을 사용하는 순차·원자적 마이그레이션 실행기.

## 실행한 검증 (2026-09-21)

- `bun run test`: 최신 23개 통과, 실DB 선택 검증 1개 생략. PDF의 파서 생성 페이지 문구 제외·빈 페이지 회귀 포함. `bun run check`: 최신 오류/경고 0. `bun run build`: 내보내기·검색 인증 묶음 조회·UI 수정 후 Vercel 패키징 성공.
- `bun run test:database`: 실제 Neon의 별도 `wiki_test_*` 스키마에서 통과. 각 트랜잭션은 `SET LOCAL search_path` 후 현재 스키마를 검사한다. 기존 본문/이력 유지, 동시 편집/게시/통합 중 단일 성공, 중간 리비전 실패의 전체 롤백, 오래된 통합 거절, 휴지통 관계 복구를 확인했다.
- `bun run test:integration`: 별도 스키마+Vite+실제 HTTP에서 생성/편집/충돌/입력 보존/별칭 제거/되돌림/휴지통/복구, DOCX 원문 초안/검사 생략/검토 게시/재시도 보호 통과. 통합안은 모의 응답을 저장해 수동 검토 필요, 사용자 수정과 상세 역사, 한 번만 적용을 확인했다. AI 키 없는 생성은 사용 불가로 안내한다.
- `bun run test:ai-merge`: 실제 OpenAI 1회, 합성 문서만 전송. `gpt-5-mini-2025-08-07`, 14,378ms, 입력 308/출력 1,322 토큰. 점검 주기 7일→3일 충돌 기록과 새 값 우선, 무관한 보관 지침 유지 확인. 실제 AI와 HTTP/DB 통합을 한 요청으로 검증한 것은 아니다.
- 브라우저: 360/768/1440px 문서 화면에서 가로 넘침 없음. RFCC 라이트/다크, 모바일 검색·문서·초안·토론, 현재 입력 미리보기, 이동 확인과 임시 입력 복구 확인. 모달 닫기 고정/배경 잠금 및 Escape 복구 확인. 360×640 모달 내부 scrollTop 0→122, X 상단 좌표 37.203125px 고정과 Escape 후 스크롤 복구를 측정했다. 다크 검색/문서/편집/역사/지도는 360/768/1440px에서 가로 넘침 없음. 업로드 후 원문 구간과 새로고침한 작업 상세의 동일 초안 연결 확인. 200% 확대·전체 키보드 흐름은 추가 검증 필요.
- 실행 Node는 로컬 24.19.0, Bun 1.4.2. 배포 목표 Node22의 실제 Vercel 요청 크기/시간 제한 및 배포 성공은 미검증.

## 연결 DB와 미해결 작업

현재 `.env`의 DB에는 이 체크아웃과 다른 계열의 13개 마이그레이션 이력이 있다. 최초 검사에서는 `001_initial.sql` 체크섬 불일치로 중단했으나, 최종 읽기 전용 재조회에서는 001이 일치했다. 이후 12개 이력과 계정·출처·리비전 구조는 여전히 다르다. 이력을 덮어쓰거나 본 변경을 public 스키마에 적용하지 않았다. 사용자가 전달한 URL로 현재 Neon DB를 적용 대상으로 확정했고, 기존 `.env` 설정과 일치하며 실제 연결에 성공했다. 기존 GitHub 연동을 사용한다는 사용자 지시에 따라 별도 Vercel 연결 작업은 제외한다. 현재 기본 개발 서버에서는 기존 자료 읽기를 확인했으며 새 쓰기 기능은 격리 환경에서만 검증했다.

최초 격리 테스트에서 연결 풀러가 시작 옵션 `search_path`를 무시해 public에 테스트 문서 ID95(`legacy`, 합성 본문)와 리비전 ID125–143을 추가했다. 기존 문서 본문/기존 이력은 변경하지 않았다. 19개 리비전은 모두 같은 테스트 INSERT 시각 `2026-09-21 09:25:36.131003+00`이며 원래 18개 문서의 당시 본문 사본과 테스트 문서 사본이다. 테스트 추가분 삭제는 자동 승인 검토에서 거절되어 사용자의 명시적 삭제 승인을 요청했다. 승인 전에는 제거하지 않는다. 이후 모든 검증은 트랜잭션 내부의 스키마 설정·검증으로 변경했고 격리 테스트가 통과했다.

## 추가 검증과 측정

- 선택 게시 HTTP: 각 초안의 명시적 검토 기록, 검토 후 변경 시 전체 취소, 중복 요청 거절, 태그·추출 원문의 게시 후 보존 통과.
- 업무 예시: 새 환경에 게시 6개/초안 1개, CDU 등 별칭과 예시 상태, 재실행 0개 추가, 사용자 편집 보존 통과.
- 업로드 DB: 두 번째 초안 저장에 주입한 실패에서 전체 롤백, 동시 완료 요청 한 번 반영, 오래된 시도 거절 통과.
- 로그인 HTTP: 익명 페이지/검색/API 차단, 네 역할의 행동 범위, Origin 검사, 작성자 위조 무시, 세션 쿠키 HttpOnly/SameSite, 역할 변경/비활성화/로그아웃/만료의 세션 취소, 마지막 운영 계정 보호, 로그인 시도 제한 통과.
- 협업 HTTP(마이그레이션 016까지): 읽기 역할의 제안은 원문을 바꾸지 않음, 검토자만 한 번 승인, 검토자 최종 수정과 실제 리비전 연결, 토론 해결/재개/답글 권한, 오래된 제안 승인 거절/반려 통과.
- 개인화 HTTP(015까지): 계정 ID 위조 무시, 즐겨찾기·최근·구독 분리, 실제 변경/담당자 알림, 권한 변경 후 목록·알림 제외, 본인 정보만 삭제 통과.
- 문서 묶음 HTTP(017까지): 본인만 수정, 비공개·공유 목록 분리, 문서 순서 보존, 오래된 버전 거절, 읽기 권한 필터, 접근 불가 항목 제외의 명시적 확인 통과.
- 문서 전환 HTTP(019까지): 이름 변경 전 주소 유지, 제목 충돌과 오래된 요청 거절, 두 게시 문서의 원본 본문/역사/별칭/연결 보존, 병합 시 엄격한 읽기 권한 승계, 중복 병합 거절, 운영 계정만 전체 상태 복원, 기록된 메타데이터의 정확한 복원과 이후 생긴 주소 유지 통과.
- 수명 관리 HTTP(014까지): 문서 접근/보관 필터, 최신 버전의 실제 검토와 담당자/기한 기록, 검토 기한 목록, 읽기 범위 변경은 운영 역할만 허용 통과.
- 실제 OpenAI 답변 1회: 합성 근거 2개, 실제 출처 ID만 반환, gpt-5-mini-2025-08-07, 4,893ms, 입력 412/출력 324 토큰. 전체 HTTP+DB+AI 한 요청 검증과 구분한다.

## 후속 요청: AI 문서 개요와 검색 트렌딩

- AI 단일/다중 초안·기존 문서 통합의 공통 지침에 첫 개요를 추가했다. 생성 결과에서 빠진 개요는 이미 생성된 요약이나 본문의 설명 문단으로 보완한다. 원문에 없는 사실을 만들지 않으며 기존 게시 문서는 변경하지 않는다. 실제 OpenAI 합성 입력 1회에서 의미별 두 문서 모두 첫 섹션 `개요`를 확인했다(21,649ms, [원자료](overview-ai-verification.json)).
- 025 마이그레이션은 검색 이벤트·집계 함수를 추가한다. 현재 사용자 미리보기 스키마에 025만 적용했고 기존 문서/초안을 보존했다. public에는 적용하지 않았다. 최근 1시간 상위 10개, 30초 화면 갱신, 실제 검색 제출·자동완성 선택·순위 선택만 집계한다. 반복은 이용자/검색어/5분 구간당 한 번이며 최대 20건이다.
- `bun run test:trending`: 별도 Neon 스키마 001–025에서 빈 순위, 대소문자 통합, 중복 제거, 이용자별 합산·정렬, 현재/과거 권한, 보관/삭제 제외, 1시간 만료·정리, 상위 10개·20건 한도 통과. 해당 테스트 스키마는 정리했다([원자료](search-trending-verification.json)).
- 현재 5185 HTTP에서 자동완성 조회는 집계하지 않고, 결과 없는 검색어·연락처는 저장하지 않는 것을 확인했다. 실제 브라우저에서 빈 순위→RFCC 검색→홈 `1 RFCC 1회`→순위 선택 후 검색 결과 이동을 확인했다. 실제 OpenAI 검증은 생성 함수 호출이며 이번에 업로드·게시 전체 흐름을 다시 실행한 것은 아니다.

- 최신 단위 검사 27개 통과, 선택 실DB 1개 생략. Svelte 오류/경고 0, Vercel 패키징 성공. 이 두 기능의 완료는 전체 로드맵의 실제 배포·사용성 검증 완료를 뜻하지 않는다.

## 기존 DB의 복사본 호환 검증

- 최신 읽기 전용 확인에서 public은 문서 25개, 초안 17개, 별칭 66개, 리비전 46개이며 계정·업로드·협업 테이블은 비어 있었다. 실제 데이터가 존재하는 범위를 기준으로 `test:legacy-rehearsal`을 추가했다. 계정·업로드·협업 데이터가 생기면 매핑 없이 진행하지 않는다.
- 실제 Neon의 하나의 반복 가능한 읽기 트랜잭션에서 원본 23개 테이블의 복사본과 독립 serial 시퀀스·외래 키, 함수 21개·뷰 2개·트리거 8개를 준비했다. 복사본의 기존 쓰기 트리거만 중지하고 겹치는 열은 `legacy_*`로 보존한 뒤 새 002–025를 적용했다.
- 첫 실행은 compact 검색에서 생략되는 전체 개수를 0으로 해석한 검증 단정이 실패해 전체 롤백됐다. 전체 개수를 반환하는 검색으로 수정하고 기존 함수·뷰·트리거까지 포함한 최종 검증을 실행했다. 원본 전체 행·열 값 대조, 분류 보존 매핑, 66개 별칭 목적지, 원래 리비전 스냅샷 보존, 현재 검색 25개, 합성 문서와 리비전의 새 저장, 외래 키·serial 기본값의 복사본 내부 연결이 통과했다.
- 46개 리비전 중 25개의 실제 스냅샷은 새 메타데이터 형식으로 연결했지만 당시 출처 관계는 기록되지 않았으므로 완전한 v3 상태로 표시하지 않았다. 스냅샷이 없던 21개는 새 메타데이터도 비워 두었다. 원래 스냅샷 자체는 유지한다.
- 성공 후 전체 롤백과 복사본 스키마 부재를 확인했다. [원자료](legacy-upgrade-rehearsal.json). 이는 원본 DB 적용·미리보기 전환·실배포 또는 실제 데이터가 없는 계정/업로드 도메인의 변환 검증을 의미하지 않는다. 원본 테스트 추가분 삭제도 수행하지 않았다.

- 최신 자료로 복사본 호환 검증을 다시 실행해 문서 33개·초안 23개·별칭 81개·리비전 54개의 보존, 002–025 적용과 검색·저장을 확인했다. 성공 후 전체 롤백과 복사본 제거를 확인했으며 원본과 개발 화면의 사용자 자료는 유지했다. [최신 결과](legacy-upgrade-rehearsal.json).

## 개발 자료 영구 보존（2026-09-21）

- 개발 화면이 사용하던 자동 정리 대상 스키마를 `wiki_development`로 전환했다. 스키마를 새로 복사하거나 자료를 재생성하지 않고 동일한 스키마의 이름만 변경했다. 31개 테이블 전체 행의 전후 지문과 스키마 객체 ID가 일치했고 문서 15개·초안 21개·리비전 36개·업로드 작업 8개 및 관련 자료가 유지됐다. public은 변경하지 않았다. [검증 기록](development-schema-verification.json).
- `WIKI_DB_SCHEMA`를 웹 서버와 마이그레이션·시드·계정 생성 CLI에 함께 적용했다. Git 제외된 `.env.local`에 영구 개발 스키마를 저장했으며 일반 `bun run dev --host 127.0.0.1 --port 5185 --strictPort`로 재시작했다. 이전 테스트 세션도 정상 종료했고 영구 자료는 유지됐다. 로그인 생략·완화 정책은 기존 설정을 유지한다.
- `test:schema` 실제 Neon 검증에서 영구/테스트 스키마 격리, 반복 풀러 요청, 롤백, 존재하지 않는 스키마 거절을 확인했다. 테스트 전용 두 스키마는 정리했다. 단위 검사 29개 통과·선택 실DB 1개 생략, Svelte 오류/경고 0, Vercel 빌드 패키징 성공. 현재 서버의 홈·검색·초안·업로드·위키파이어·트렌딩 HTTP 200 및 `bun run migrate`의 25개 기존 이력 일치를 확인했다.

## 개발 모드의 선택적 계정 로그인

- 사용자의 Operator-24 관리 화면 요청에 맞춰 `/login?account=1&handle=Operator-24&next=%2Fadmin%2Fusers`를 추가했다. 이름은 미리 채울 뿐이며 기존 비밀번호 검증·세션 발급·서버 역할 검사를 거친다. 일반 `/login`의 개발 모드 우회와 로그인 없는 읽기/작성 흐름은 유지한다.
- 실제 HTTP에서 Operator-24 로그인, 관리자 사용자 목록의 정상 표시, 익명 홈 200, 일반 로그인 경로의 기존 303을 확인했다. 검증용으로 발급한 두 번째 세션은 로그아웃했다. 첫 검증은 HTML Accept 헤더 없이 전송해 SvelteKit의 200 액션 응답을 303으로 예상한 단정이 실패했다. HTML 요청으로 다시 확인해 통과했으며 첫 세션은 만료 정책에 따라 정리된다. 비밀번호는 검증 기록에 보관하지 않는다.
- 단위 검사 29개 통과·선택 실DB 1개 생략, Svelte 오류/경고 0.

## 후속 요청: 메인 토론 바로가기와 관리자 메뉴 정리（2026-09-22）

- 기본 메인 화면과 최근 활동에 읽을 수 있는 최근 토론 5건을 표시한다. 토론 제목은 해당 토론을 선택하고 본문 위치로 이동하며, 별도의 문서 읽기 링크는 원래 문서로 연결한다. 삭제·보관 문서와 접근할 수 없는 토론은 기존 권한 필터로 제외한다.
- 관리자 계정의 문서·토론 화면에서 수정 제안과 검토·관리 진입 메뉴를 제거하고 계정 메뉴의 정기 검토도 제외했다. 이번 요청은 관리자 화면 구성을 변경하며 저장된 제안·검토 기록이나 서버 기능은 삭제하지 않는다. 일반 계정·검토자 화면은 유지한다.
- 실제 Operator-24 브라우저에서 메인→최신 항목이 아닌 특정 토론 선택→해당 토론 본문, 메인→문서 읽기→실제 문서, 관리자 문서 메뉴의 편집·역사·토론만 표시되는 동작을 확인했다. 360×780 화면에서 토론 제목·문서 링크를 확인했고 페이지 너비 360px로 가로 넘침이 없었다. 검증 탭과 화면 크기 설정을 정리했다.
- 단위 검사 29개 통과·선택 실DB 1개 생략, Svelte 오류·경고 0, Vercel 빌드 패키징 성공. 기존 운영 전환·배포 조건의 완료를 뜻하지 않는다.

## 관리자 기능 제거의 서버 적용 및 DB 검증 생략（2026-09-22）

- 이전의 관리자 메뉴 제거를 서버 조회·액션까지 확장했다. 관리자 역할은 수정 제안·검토/관리·정기 검토 경로에서 403을 받고, UI도 같은 경로 정책을 사용한다. 문서 편집·토론·역사·계정 관리와 다른 역할의 기존 권한은 유지한다.
- 관리자 알림의 제안 링크는 문서/토론으로 연결하고, 역사에는 승인한 제안 번호와 변경 내용을 텍스트로 유지한다. 기존 데이터와 DB 함수는 삭제하지 않았다.
- 단위 검사 30개 통과·선택 DB 1개 생략, Svelte 오류·경고 0, Vercel 빌드 패키징 성공. 실제 Operator-24 브라우저에서 관리 경로 403, 제안 승인 기록이 남은 역사, 정상 계정 관리 화면을 확인했다.
- `bun run test:auth --port=5187`은 연결 단계가 지연되던 중 사용자가 DB 통합 검증 생략을 명시하여 중단했다(종료 130). 이번 변경의 DB/HTTP 통합 검증을 통과로 기록하지 않는다. 새 역할 조건의 검증 시나리오와 격리된 과거 기록 준비용 도우미는 코드에 남겼으며, 사용자 요청 없이 다시 실행하지 않는다.
- 사용자는 해당 Neon DB를 이 위키만 사용한다고 확인했다. DB 통합 검증은 최종 필수 검사에서 제외한다. 실제 데이터 전환이나 배포가 수행됐다는 뜻으로 해석하지 않는다.

## 오류 화면의 복귀 동선（2026-09-22）

- 관리자 기능의 직접 접근 차단은 서버 훅에서 발생해 기존 Svelte 오류 컴포넌트 대신 프레임워크 기본 화면을 표시했다. 실제로 홈 복귀 링크가 없었던 상태를 확인하고, 앱 번들 없이도 동작하는 한국어 `src/error.html`에 안내·홈 이동·서버 오류 재시도를 추가했다.
- 일반 오류 화면도 권한 제한·없는 페이지를 연결 장애로 잘못 안내하지 않도록 제목을 구분했다. 403/404에서는 홈 이동을, 서버 오류에서는 재시도도 제공한다.
- 실제 관리자 403 화면의 360px 라이트/다크 배치와 가로 넘침 없음, Tab 초점 표시와 Enter로 홈 이동을 확인했다. 없는 경로의 HTTP 404·올바른 안내·홈 링크도 확인했다. 검증 테마와 화면 크기를 복원하고 임시 탭을 닫았다.
- 단위 검사 30개 통과·선택 DB 1개 생략, Svelte 오류·경고 0, 빌드·서식 검사 통과. DB 통합 검증은 사용자 요청대로 실행하지 않았다.

## 실제 DB 전환 명령과 공유 검증

- 복사본 전용 로직을 `legacy-upgrade.js`로 분리하고 `migrate:legacy` 명령을 추가했다. 명시한 스키마의 읽기 전용 사전 검사가 기본이며 실제 적용에는 기존 앱의 쓰기 중지가 필요하다. 별도 보존본에는 원본 행·독립 시퀀스와 설정·함수 21개·뷰 2개·트리거 8개를 보관한다. 기존 자료 대조와 새로운 구조 적용을 한 트랜잭션에서 처리한다. 성공 기록은 대상 DB에도 남기고 재실행은 기존 보존본을 유지한다.
- 실제 적용 함수를 사용하는 Neon 복사본 검증이 통과했다. 최신 원본의 문서 42개·초안 52개·별칭 81개·리비전 63개를 보존했고 새 문서가 리비전 하나만 생성함을 확인했다. 반복 적용은 추가 마이그레이션/보존본 없이 끝났고, 기존 앱처럼 새 계정 컨텍스트 없이 쓰는 요청은 거절됐다. 전체 롤백 후 두 검사 스키마의 부재를 확인했다. [결과](legacy-upgrade-rehearsal.json).
- `bun run migrate:legacy --schema=public`의 읽기 전용 사전 검사도 통과했다. 원본 적용은 하지 않았다. 기본 DB에 별도로 계속 자료가 추가되어 기존 사용처를 질문했으며, 사용처 확인 없이 쓰기가 중지됐다고 가정하지 않는다. 새 Vercel 연결 요청은 하지 않는다.
- 선택적 관리자 로그인 수정 후 빌드도 Vercel 패키징까지 통과했다.
