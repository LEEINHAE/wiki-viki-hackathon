# Wiki Viki 프로토타입 반영

사용자가 제공한 `Wiki Viki Prototype.html`의 화면, 스타일 및 상호작용을 기존 SvelteKit 앱에 구현했습니다. 첨부 파일의 스크립트는 기능을 파악하기 위한 참고 자료로만 사용하고, 앱에서는 기존 서버·데이터베이스에 연결한 Svelte 컴포넌트를 사용합니다.

## 실제 데이터와 예시의 구분

홈의 숫자와 목록은 저장된 문서·리비전·초안을 기준으로 계산합니다. 프로토타입의 고정 수치(1,812개 문서 등)를 실제 통계로 표시하지 않습니다. 예시 문서 제목은 위키파이어의 **공장약어집.pdf 예시로 시연**에서 확인할 수 있습니다. 실제 파일을 읽었다고 표시하거나 AI를 호출한 것처럼 시연하지 않습니다.

문서 조회수는 문서를 연 브라우저 세션당 한 번 증가합니다. `[[문서]]`와 별칭을 해석해 관련 문서·역링크·지도 연결을 계산합니다. 아직 초안인 문서의 링크는 초안 검토 화면으로 연결됩니다. 검색의 설명은 문서에 저장된 설명 또는 본문 발췌이며, 별도의 생성형 질의응답이 아닙니다.

## 저장과 마이그레이션

`bun run migrate`는 migrations 디렉터리의 SQL을 순서대로 적용합니다. `002_prototype_features.sql`은 기존 데이터를 유지하며 분야·설명·출처·조회수 열을 추가합니다. 다중 초안 생성은 한 트랜잭션으로 저장하며, 게시할 때 문서·최초 리비전·별칭·초안 상태를 한 번에 기록합니다. 기존 문서를 덮어쓰거나 이미 게시한 초안을 다시 게시하지 않습니다.

## AI와 원문 초안

AI 연결은 기존 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 사용합니다. 다중 초안의 응답 형식은 [OpenAI Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고했습니다.

API 키가 없거나 사용자가 오류 화면에서 **원문으로 기본 초안 만들기**를 선택하면 원문을 보존한 단일 초안을 생성합니다. 이 경로와 프로토타입 시연은 의미 기반 AI 검사를 수행하지 않으며 검토 화면에 생략 사실을 표시합니다. 정규식 검사는 유지됩니다. AI 오류를 성공으로 표시하거나 자동 게시하지 않습니다.

2026-09-21 확인 시 연결된 API는 `429 / credit_balance_exhausted`를 반환했습니다. 실제 AI 다중 초안 생성은 계정 크레딧 보충 후 추가 확인이 필요합니다. 시연 초안 및 원문 초안의 전체 게시 흐름은 검증했습니다.

## 검증

- `bun run test`: 검색 정렬·필터, 링크 해석·자동 연결, 익명 식별자, PDF·PPTX 추출, 파일 검증.
- `bun run test:integration`: 실행 중인 로컬 서버에서 문서 생성·검색·별칭·역링크·편집·이력·토론·되돌리기 및 시연 초안 수정·게시·중복 방지. 이번 실행에서 만든 데이터만 정리합니다.
- `TEST_UPLOAD=1 bun run test:integration`: DOCX 파일로 원문 초안 생성도 확인합니다.
- `TEST_AI_UPLOAD=1 bun run test:integration`: AI 크레딧을 사용하는 실제 DOCX 변환도 확인합니다.
- `bun run check`, `bun run build`: Svelte 검사 및 배포 빌드.

파일은 40MB까지 허용하지만, 실제 배포 서비스나 프록시의 요청 크기·실행 시간 제한도 적용됩니다. 스캔 PDF와 이미지 슬라이드의 OCR은 지원하지 않습니다. 추출한 텍스트는 12만 자, 압축을 푼 Office 파일은 150MB까지 허용합니다.
