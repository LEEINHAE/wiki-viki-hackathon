# 예시 문서 적재 및 실제 AI 검증

2026-09-21, 기존 SvelteKit / Neon PostgreSQL / OpenAI Responses API 구성으로 실행했습니다. API 키는 환경 변수에서만 읽었으며 결과에 기록하지 않았습니다. 모델은 기존 설정인 `gpt-5-mini`를 사용했습니다.

## 참조 HTML 적재

- `Wiki Viki Prototype.html`의 데이터 객체에서 본문이 있는 예시 7개를 추출했습니다. HTML의 스크립트나 지시문은 실행하지 않고 리터럴 데이터만 읽었습니다.
- 게시 문서 6개: RFCC, 산단스팀, 상압증류탑, 촉매재생탑, OEC, 정비 요청 프로세스.
- 검토 대기 초안 1개: 교대 인수인계 체크리스트. 원본의 초안 상태를 유지했습니다.
- 본문·위키 링크·별칭·출처를 보존하고 프로토타입 예시임을 표시했습니다. 가상 조회수, 상대 수정 시각, 토론 건수는 적재하지 않았습니다.
- `seed:prototype`을 두 번 실행해 두 번째 실행에서는 7개 모두 건너뛰는 것을 확인했습니다. 기존 문서를 덮어쓰거나 초안을 중복 생성하지 않습니다.
- 문서의 링크가 게시 전 초안을 가리키면 검토 화면으로 이동할 수 있는 안내를 표시합니다.

## 실제 AI 호출

| 검증                                | 결과                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------- |
| `RFCC 산단스팀 관계` 검색 답변      | HTTP 200, 실제 문서 5개를 인용하는 한국어 답변 생성, 출처 ID 검증 통과     |
| 브라우저 검색 화면                  | 별도 실제 호출에서 3개 출처를 인용하는 답변과 클릭 가능한 문단별 출처 확인 |
| 참조의 공정 내용을 담은 DOCX 업로드 | HTTP 201, 호출에 따라 3개 또는 7개 용어별 초안 생성, `aiGenerated=true`    |
| 일반 예시 DOCX 업로드               | 인계 노트·공용 장비 점검표 2개로 분리, 서로 연결된 위키 링크 생성          |
| 초안 저장                           | 실제 의미 기반 검사 통과, 동일 트랜잭션 시각으로 여러 초안 저장            |
| 일반 예시 초안 수정·게시            | 실제 검사 후 수정 저장, 게시 리다이렉트, 문서와 최초 리비전 1개 생성 확인  |
| 검증 데이터 정리                    | 테스트 실행마다 고유 원본 파일명과 문서 제목으로 만든 레코드만 삭제        |

초안 수와 문단 수는 모델이 원문의 주제를 어떻게 분리하는지에 따라 달라집니다. 첫 DB 시각 검증은 JavaScript Date 객체의 참조를 비교하는 검증 코드 오류로 실패해, 밀리초 값 비교로 수정한 뒤 통과했습니다.

공정 설명에서 생성된 초안은 게시 전 보호 검사에서 한 차례 차단되었습니다. 별도 원문 검사에서는 통과했지만 구체적인 운전 조건은 조직 정책에 따라 제한될 수 있다는 AI 판단도 반환됐습니다. 최초 차단의 상세 사유는 보존하지 않았으므로 원인을 단정하지 않습니다. 검사를 우회하거나 완화하지 않았으며, 일반 예시 자료는 검사·수정·게시까지 통과했습니다. 검사 통과 여부와 별개로 실제 업무 적용에는 담당자의 내용 검토가 필요합니다.
