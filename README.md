# Wiki Viki

SvelteKit, JavaScript, Bun, PostgreSQL 및 OpenAI Responses API로 만든 문서 중심의 사내 위키입니다.

## 설치 및 실행

`.env.example`을 `.env`로 복사하고 `DATABASE_URL`을 설정하세요. OpenAI API 키는 선택 사항입니다. API 키가 없어도 DOCX/PDF/XLSX/PPTX에서 추출한 텍스트로 기본 초안 하나를 만들 수 있으며, 이 경우 의미 기반 콘텐츠 보호 검사는 건너뜁니다.

```bash
bun install
bun run migrate
bun run seed
bun run dev
```

`bun run seed`는 Wiki Viki 운영에 필요한 정책·도움말 문서를 만들고 `seed-data/`의 DOCX/PDF 파일을 처리합니다. 파일명과 원문이 공통 로컬 검사를 통과한 뒤에만 의미 검사와 AI 구조화를 수행합니다. 차단·검사 실패·잘못된 생성 결과는 새 초안으로 저장하지 않습니다. 키가 없으면 안전한 원문으로 기본 초안을 만들며 의미 검사 생략을 초안과 로그에 표시합니다.

기본 문서는 기존 제목·주소·별칭과 충돌하면 건너뜁니다. 주소가 다른 별칭도 표시 이름이 새 제목과 정확히 같으면 충돌로 처리하며 휴지통 문서의 이름도 보존합니다. 재실행해도 기존 본문·작성자·시각·리비전·관계 데이터와 환영 공지를 변경하지 않습니다. 새 기본 문서와 첫 리비전, 환영 공지는 한 트랜잭션으로 저장하므로 중간 실패 시 이 묶음을 모두 취소합니다. 동시 실행은 기본 초기화 구간에서 직렬화하며, 실제 생성·건너뜀 개수를 출력합니다. 기본 초기화나 잠금 대기가 실패하면 종료 코드 1로 끝나고 파일 처리를 시작하지 않으므로 원인을 해결한 뒤 재실행할 수 있습니다.

기본 초기화 후 특정 파일이 실패해도 다음 파일을 계속 처리합니다. 로그에는 파일명을 정렬한 순서의 번호, 처리 단계·결과와 실제 생성·차단·실패·검사 생략 개수를 표시하며, 파일명·원문·내부 오류는 출력하지 않습니다. 읽기·AI·DB 실패가 있으면 마지막에 종료 코드 1을 반환합니다. 차단만 발생한 경우에는 차단 개수를 확인하세요. 원본 파일을 재처리할 때 초안이 중복 생성되는 기존 동작은 별도 개선 항목입니다.

일반 기능 확인용 예시 5개는 `bun run seed:demo`로 적재합니다. 기존 활성 문서와 휴지통 문서의 제목·대표 주소·별칭 중 하나라도 충돌하면 그 예시 전체를 건너뜁니다. 새 제목·별칭은 기존 제목·별칭의 실제 표시 이름과도 비교하므로 주소가 달라도 같은 이름을 추가하지 않습니다. 사용자 편집·시각·이력·별칭 대상을 바꾸거나 사용자가 제거한 별칭을 되살리지 않습니다. 새 문서·첫 리비전·별칭은 다섯 예시의 한 트랜잭션으로 저장하며, 중간 실패 시 이번 실행의 생성분을 모두 취소합니다. 동시 실행과 진행 중 편집/이름·주소 선점을 잠금으로 보호하고, 커밋 후 실제 생성·건너뜀 개수만 출력합니다. DB/잠금 실패는 종료 코드 1로 끝나므로 상태를 확인한 뒤 재실행하세요. 기존 문서의 내용을 최신 예시로 교체하는 명령은 아닙니다.

참조 HTML의 예시 문서는 `bun run seed:prototype`으로 적재합니다. `seed-data/prototype-documents.json`에는 원본의 본문·별칭·출처를 추출해 보관했습니다. RFCC, 산단스팀, 상압증류탑, 촉매재생탑, OEC, 정비 요청 프로세스는 게시 문서로, 교대 인수인계 체크리스트는 원본처럼 검토용 초안으로 생성합니다. 모든 문서에 프로토타입 예시임을 표시합니다. 원본 화면의 조회수·상대 시각·토론 건수는 가져오지 않습니다.

이 명령은 기존 활성/휴지통 문서·별칭의 이름과 주소, 기존 초안의 제목·주소·별칭과 충돌하면 예시 전체를 건너뜁니다. 이름을 바꾼 기존 참조 초안도 저장된 출처 정보를 확인해 다시 만들지 않습니다. 일반 문서/초안 쓰기와 같은 테이블 잠금으로 진행 중 변경을 기다린 뒤 검사하고, 일곱 예시의 문서·첫 리비전·별칭·초안을 한 트랜잭션으로 반영합니다. 중간 실패나 누락은 전체 취소하며 커밋 후 실제 항목별 결과만 JSON으로 출력합니다. 잠금 대기나 DB 오류는 내부 정보를 노출하지 않고 종료 코드 1로 끝나므로 상태를 확인한 뒤 재실행하세요. 반복 실행으로 사용자 편집·제거한 별칭·기존 초안을 되돌리지 않습니다. 본문에서 아직 게시되지 않은 초안을 가리키는 링크를 열면 초안 검토 화면으로 이동할 수 있는 안내가 표시됩니다. Node.js 환경에서는 `node --env-file=.env scripts/seed-prototype.js`로 같은 작업을 실행할 수 있습니다.

## 데이터베이스 마이그레이션

`bun run migrate`는 `migrations/`의 `NNN_name.sql` 파일을 숫자 번호순으로 적용하고, 대상 연결의 현재 스키마에 `schema_migrations`를 기록합니다. 파일명·번호·SHA-256·적용 시각을 저장하며 이미 적용한 파일은 다시 실행하지 않습니다. 파일은 UTF-8로 작성하고, 새 변경은 현재 최대 번호보다 큰 새 파일로 추가하세요. 적용된 파일의 내용·이름·번호·줄바꿈을 바꾸거나 삭제하면 실행을 거부합니다. 같은 번호를 중복하거나 이미 적용한 번호 사이에 새 파일을 끼워 넣을 수도 없습니다.

기존 실행기로 `001_initial.sql`을 적용한 DB는 같은 파일을 보존한 채 실행하면 됩니다. 기존의 `CREATE ... IF NOT EXISTS`를 실행해 필요한 초기 구조를 확인하고 적용 이력을 추가하며, 문서·ID·주소·본문·시각·리비전·별칭·토론·초안·공지 데이터를 수정하지 않습니다. 초기 구조와 다른 수동 스키마 변경이 있다면 이력만 강제로 추가하지 말고 실제 스키마를 먼저 확인하세요. `002_document_trash.sql`은 기존 문서에 삭제 시각·익명 삭제자·삭제/복구 버전 카운터를 추가합니다. 기존 행은 미삭제 상태로 시작하고 모든 내용과 관계를 유지합니다.

동일 DB·스키마의 실행은 트랜잭션 잠금으로 직렬화합니다. **한 번의 실행에서 미적용 SQL 전체와 이력을 함께 커밋**하며, 중간 SQL/이력 기록 실패 시 이번 실행의 변경을 모두 취소하고 이전에 커밋된 이력은 유지합니다. 기본 잠금 대기 제한은 10초입니다. 성공 로그는 커밋 후 실제 적용·기존 적용 개수를 출력합니다. SQL 파일에 `BEGIN`/`COMMIT`/`ROLLBACK` 등 트랜잭션 제어를 넣지 마세요. 함수와 `DO` 블록은 달러 인용 본문을 사용하고, 트랜잭션 안에서 실행할 수 없는 `CREATE INDEX CONCURRENTLY` 같은 문장은 이 실행기에 넣지 않습니다. 파일 안의 데이터 보충도 같은 트랜잭션에 포함해야 합니다.

실패하면 종료 코드 1과 안전한 안내를 반환합니다. 연결 단절로 완료 여부가 불확실할 때도 성공으로 표시하지 않습니다. 복구 순서는 다음과 같습니다.

1. 연결·권한·잠금 또는 표시된 DB 오류 코드를 확인합니다. 적용 이력은 `SELECT version, name, checksum, applied_at FROM schema_migrations ORDER BY version;`으로 조회합니다. 첫 실행 전체가 취소됐다면 이 테이블도 아직 없습니다.
2. 파일/이력이 다르면 배포한 원래 파일을 복원합니다. 적용 이력을 지우거나 체크섬을 덮어써 검사를 우회하지 않습니다. 미적용 SQL 오류는 미적용 파일에서 고칠 수 있으며, 이미 적용한 변경의 수정·데이터 보충은 새로운 번호의 마이그레이션으로 작성합니다.
3. 기존 데이터가 있는 격리 DB에서 보존·실패 복구를 확인한 뒤 같은 `bun run migrate`를 재실행합니다. 이미 커밋된 번호는 건너뛰므로 응답 유실 뒤 재실행도 중복 적용하지 않습니다. 롤백된 INSERT가 소모한 시퀀스 번호에 빈칸이 생길 수 있으므로 번호를 다시 맞추거나 재사용하지 않습니다.

## 휴지통과 문서 복구

편집 화면에서 확인 항목을 선택하고 **휴지통으로 이동**하면 저장된 문서·리비전·별칭·토론과 게시 초안의 연결을 보존합니다. 현재 입력한 미저장 내용은 보관 대상에 포함되지 않으며, 이동 실패 시에는 입력을 화면에 유지합니다. 검토한 문서나 별칭이 바뀌면 이동을 거부하고 현재 문서를 다시 확인하도록 안내합니다.

휴지통 문서는 일반 읽기·편집·이력·토론·검색·자동완성·AI 설명의 근거·최근 변경·지도/관련 문서 목록에서 제외됩니다. 원래 주소와 별칭 주소를 열면 휴지통으로 연결하는 안내를 표시합니다. 제목·주소·별칭은 보관 중에도 예약하여 다른 문서가 차지하지 않게 합니다. 기존 다른 문서의 본문에 쓰인 링크 텍스트는 유지합니다.

상단의 **휴지통**에서 문서와 보관 본문·별칭을 확인하고 **문서 복구**를 누르세요. 목록은 이동 시각순으로 50개씩 탐색하며 복구는 원래 ID·대표 주소·내용·수정 시각과 관계를 되살립니다. 이미 다른 요청이 처리했거나 검토 버전이 바뀌면 중복 처리하지 않습니다. 다른 문서가 실제 대표 주소나 별칭 주소를 사용하고 있으면 관계를 덮어쓰지 않고 복구를 중단하므로 충돌을 해결한 뒤 다시 시도해야 합니다. 복구는 저장된 주소와 이름을 그대로 되살리며 새 주소를 만들지 않습니다. 따라서 이미 존재한 표시 이름 중복이나 제목에서 계산한 미사용 주소는 복구를 막지 않습니다. 영구 삭제나 자동 비우기는 제공하지 않습니다. 도입 전에 영구 삭제된 자료를 새 휴지통으로 복구할 수는 없습니다.

이 버전을 적용하려면 `bun run migrate`가 먼저 필요합니다. 전환 중에는 구버전의 영구 삭제 요청이 남지 않도록 쓰기 작업을 멈추고 마이그레이션과 새 서버 버전 적용을 함께 진행하세요. 운영 DB 적용·배포 검증은 로컬 통합 검사와 별개입니다.

## Vercel 배포

[Vercel용 SvelteKit 어댑터](https://vercel.com/docs/frameworks/full-stack/sveltekit)를 사용하며, 서버 코드는 Node.js 22 런타임에서 실행됩니다.

1. Vercel에서 저장소를 가져오고 Framework Preset을 **SvelteKit**, Node.js Version을 **22.x**로 설정합니다.
2. Install Command는 `bun install --frozen-lockfile`, Build Command는 `bun run build`로 설정합니다. Output Directory는 기본값을 유지합니다.
3. 환경 변수에 Neon PostgreSQL 연결 문자열인 `DATABASE_URL`을 설정합니다. AI 기능을 사용하려면 `OPENAI_API_KEY`를 추가하고, 필요하면 `OPENAI_MODEL`도 설정합니다.
4. 배포 전에 해당 DB의 `DATABASE_URL`을 설정한 로컬 환경에서 `bun run migrate`를 실행합니다. 초기 데이터가 필요하면 `bun run seed`도 실행한 뒤 배포합니다.

별도의 `vercel.json`은 필요하지 않습니다. 마이그레이션과 시드는 배포 빌드에서 자동 실행되지 않습니다.

## 문서 자동 연결

문서 본문의 제목·등록 별칭은 별도 검토 없이 다른 게시 문서로 자동 연결됩니다. 한국어 조사와 영문 대소문자를 처리하고, 같은 대상은 한 번 연결합니다. 본문에 저장한 수동 링크는 우선하며 코드·이미지·주소·기존 링크 내부, 자기 문서, 모호한 이름, 숫자만 있거나 한 글자인 이름은 자동 연결하지 않습니다. 관련 문서·역링크·홈 통계·지식 지도에도 동일한 규칙을 적용합니다. 예를 들어 기존 인계 문서에 적힌 `RFCC`는 해당 문서가 나중에 게시돼도 다음 조회부터 링크가 됩니다.

상단 **자동 연결**(`/links`)의 **전체 검사·자동 재연결**로 최신 활성 문서 전체를 다시 검사할 수 있습니다. 실제 연결 수, 문서별 연결 대상, 연결 없는 문서, 미작성 링크와 모호한 이름을 표시합니다. 자동 연결은 원문을 덮어쓰지 않고 표시할 때 계산하므로 문서/별칭 변경·휴지통·복구를 별도 승인 없이 반영하며, 저장된 원문·리비전·수정 시각·검토 버전을 바꾸지 않습니다. 외부 AI나 API 키가 필요하지 않습니다. 의미만 비슷한 문서까지 추측해 연결하지는 않습니다.

문서의 **관련 문서**는 그 본문에서 연결한 대상이고, **이 문서를 가리키는 문서**는 다른 본문에서 들어오는 연결입니다. 각 항목에 **제목·별칭 자동 연결** 또는 **본문에 저장된 링크**와 실제 원문 표기를 보여 줍니다. 같은 대상의 반복 연결은 한 번 표시하며, 원문에 저장된 링크를 우선합니다. 링크의 설명으로도 연결 이유를 제공하고 문서 정보에서 두 방향의 문서 수를 구분합니다. 모바일에서는 본문 아래에서 확인하며 JavaScript 없는 기본 링크도 지원합니다. 같은 격리 DB/Playwright 환경의 `node tests/browser/reading-connections.mjs`로 이유·방향·키보드 탐색·긴 표기·빈/지연/조회 실패·실제 휴지통/복구를 검증합니다. 결과 경로는 `CONNECTION_BROWSER_OUTPUT`으로 지정합니다.

## 검증

```bash

bun run lint
bun run build
```

마이그레이션·초안·직접 편집·이력 되돌리기·휴지통/복구·토론 등록·시드 콘텐츠 보호 및 데이터 보존의 PostgreSQL 통합 검증은 별도로 활성화합니다. 사용자 자료와 분리된 로컬 DB를 준비하고, 이름이 `wiki_viki_test_`로 시작하는 DB의 연결 정보를 `GOVERNANCE_TEST_DATABASE_URL`에 설정한 뒤 `RUN_GOVERNANCE_DB_TESTS=1 bun run test`를 실행하세요. 테스트는 고유 스키마를 만들고 종료 시 정리합니다. 시드 검증에는 임시 DOCX/PDF와 외부 HTTP를 차단한 별도 Bun 프로세스도 사용합니다. 기본 시드와 데모 시드 보존 검사는 DB trigger로 중간 실패를 일으키고, 독립된 PostgreSQL 연결의 잠금 대기를 확인해 동시 실행을 검증합니다. 두 CLI에서 주소가 다른 제목·별칭의 표시 이름 충돌과 활성/휴지통 소유권·재실행 보존도 확인합니다. 데모 시드는 실제 Bun CLI의 전체 롤백·휴지통 포함 충돌·연결 단절·재시도와 생성/건너뜀 로그도 확인합니다. 프로토타입 적재도 실제 Bun/Node CLI에서 일곱 예시의 본문·출처·별칭 보존, 이름을 바꾼 참조 초안의 재생성 방지, 일반 쓰기와의 경합·중간 실패·연결 종료·안전한 실패 안내를 검증합니다. 플래그가 없으면 이 DB 검증은 생략되며 통과로 계산하지 않습니다. AI 응답은 전송 경계에서 모의 처리하므로 실제 OpenAI 호출 검증과 구분합니다.

직접 편집 임시 복구의 실제 브라우저 회귀는 같은 격리 DB 설정으로 `node tests/browser/edit-recovery.mjs`를 실행합니다. 별도 도구 환경의 Playwright 모듈 경로를 `PLAYWRIGHT_MODULE`로 지정할 수 있으며 설치된 Chrome을 사용합니다. 예: `RUN_GOVERNANCE_DB_TESTS=1 GOVERNANCE_TEST_DATABASE_URL='<로컬 테스트 DB 연결>' PLAYWRIGHT_MODULE='<Playwright index.mjs 절대 경로>' node tests/browser/edit-recovery.mjs`. 운영 DB는 거부합니다. 화면 캡처·JSON 결과는 출력되는 임시 디렉터리에 보관하고 외부 AI 응답은 모의 처리합니다. 일반 테스트/빌드와 순차 실행하세요.

직접 편집의 늦은 저장·삭제 응답은 같은 환경의 `node tests/browser/edit-late-response.mjs`로 검증합니다. `LATE_EDIT_BROWSER_OUTPUT`으로 결과 폴더를 지정할 수 있습니다. 실제 서버 응답을 지연해 다른 문서 작성/저장·같은 문서 재진입·편집 화면 종료 뒤 현재 입력과 복구본이 유지되는지 확인하며, 격리 DB의 중간 실패와 원래 작업 결과도 대조합니다.

초안 수정·최종 통합 편집 복구는 같은 환경에서 `node tests/browser/draft-recovery.mjs`로 검증합니다. 실제 격리 DB의 저장 실패·충돌·삭제/게시 상태와 브라우저 보관·복구·보호 정책을 함께 확인합니다. `RECOVERY_BROWSER_OUTPUT`으로 이미 만들어 둔 결과 디렉터리를 지정할 수 있습니다. 두 브라우저 스크립트도 순차 실행하세요. 업로드 허용 기준의 실제 파일→초안→게시 회귀는 같은 환경에서 `node tests/browser/relaxed-upload.mjs`로 실행합니다. 결과 경로는 `RELAXED_BROWSER_OUTPUT`으로 지정할 수 있습니다.

홈은 검색창·분야별 진입·사용 안내를 먼저 보여 주고, 실제 문서 목록 아래에 통계와 소개를 배치합니다. 분야는 기존 검색과 같은 제목 기반 분류를 사용하며, 선택한 분야의 최근 수정 문서를 최대 12개 표시합니다. 전체 개수와 표시 개수를 구분하고 휴지통 문서는 제외합니다. `/?view=search&category=업무%20절차#home-documents`처럼 선택이 URL에 남아 새로고침·뒤로 가기·공유를 지원합니다. 조회 실패에서는 문서 수를 `—`로 표시하고 명시적 다시 불러오기를 제공합니다. `node tests/browser/home-entry.mjs`로 실제 격리 DB의 분야/개수·탐색·원문 보존·빈/로딩/오류·기본 링크와 두 테마/세 화면 크기를 확인하며, 결과 경로는 `HOME_BROWSER_OUTPUT`으로 지정합니다.

전역 메뉴에서 **검색·문서 탐색·최근 변경·초안 검토**로 이동하고, **새 문서 작성**(`/new`)이나 **AI 위키파이어**를 시작할 수 있습니다. 문서 탐색은 기존 지식 지도로 연결합니다. 새 문서는 제목을 먼저 입력하며 같은 제목·주소·별칭의 문서, 휴지통 문서, 미게시 초안이 있으면 해당 대상을 안내합니다. 새 제목은 기존 편집 화면으로 이어지고 명시적으로 저장하기 전에는 생성되지 않습니다. 제목 확인이 실패하면 입력을 유지하며 같은 제목으로 다시 조회할 수 있습니다. 모든 편집 및 토론 사용자 이름은 `Editor-01` 또는 `Operator-A` 형식의 익명 식별자를 사용해야 합니다. AI 결과는 항상 초안 생성 → 담당자 검토 → 게시 절차를 거치며, 게시 전에 정규식·키워드 및 의미 기반 콘텐츠 보호 검사를 수행합니다.

콘텐츠 검사는 일반 업무 문서를 허용하는 최소 기준으로 완화했습니다. 이름·이메일·전화번호·사번·인사/급여 정보와 대외비·기밀·confidential 표시는 파일명이나 본문에 있어도 차단하지 않습니다. 주민등록번호 전체 값과 노출된 비밀번호·인증 키만 차단하며, 단순 용어 설명·환경 변수 참조·마스킹·예제 플레이스홀더는 허용합니다. 이 기준은 업로드·AI 처리·초안 저장/게시·직접 편집·토론·시드·브라우저 임시 복구에 공통 적용됩니다. AI 연결 시 허용된 내용도 기존 AI 처리 흐름으로 전송됩니다. 키 없는 기본 초안, 검토 확인, 저장 충돌/원자성 보호와 검사 장애의 재시도 처리는 유지합니다. 이전 기준으로 차단된 초안은 내용을 수정할 필요 없이 **검토 내용 저장**으로 다시 검사할 수 있으며, 저장된 초안을 자동 변경하거나 게시하지 않습니다.

## 프로토타입 화면 구현

기존 SvelteKit 2 · Svelte 5 · JavaScript · PostgreSQL/Neon · OpenAI Responses API · Vercel 구성을 유지합니다. Excel 읽기에는 `read-excel-file`, PPTX 읽기에는 기존 DOCX 파서에서도 사용하는 `jszip`·`@xmldom/xmldom`을 직접 의존성으로 등록했습니다. 파일 추출 기능은 기존 문서 스키마를 사용합니다.

- 홈: 검색 우선, 활동 대시보드, 실제 위키 링크 기반 지식 지도. 통계는 DB에서 계산하며 조회수나 방문 이력을 가정하지 않습니다.
- 검색: 제목·본문·별칭 검색, 자동완성 및 키보드 탐색, 제목 기준 분야 필터, 여러 게시 문서를 종합한 AI 설명과 문단별 출처 링크.
- 문서: 데스크톱의 고정 보조 영역에서 계층형 목차를 볼 수 있습니다. 본문 앞 **목차로 이동** 링크로 키보드에서도 바로 접근합니다. 스크롤할 때 실제 현재 문단을 굵기·왼쪽 선으로 표시하며 주소나 읽기 이력을 저장하지 않습니다. 800px 이하에서는 접이식 목차를 사용하고, JavaScript 사용 시 목차 바를 고정합니다. 문단 선택/본문 복귀는 제목에 키보드 초점을 옮기고, Escape는 목차를 닫아 열기 버튼으로 돌아갑니다. Tab이나 클릭으로 목차 밖에 나가도 닫힙니다. 화면 폭을 바꿔도 초점이 숨겨진 목차에 남지 않습니다. JavaScript 없이도 기본 목차 펼치기와 기존 문단 링크를 사용할 수 있습니다. 관련 문서·정확한 역링크·편집·역사·토론 연결과 기존 `section-N`/`document-toc` 주소를 유지합니다.
- 직접 편집: 기존 문서 ID·주소·이력을 유지하면서 본문·리비전·별칭을 한 트랜잭션으로 저장합니다. 다른 문서의 제목·주소·별칭은 덮어쓰지 않습니다. 기존 주소와 표시 이름이 다른 경우도 새 제목·별칭이 저장된 이름과 정확히 같으면 충돌로 처리합니다. 기존 문서에 이미 있던 이름과 주소는 유지하며 중복 표기를 자동 정리하지 않습니다. 기존 제목을 그대로 둔 본문 저장·되돌리기는 제목에서 새 주소를 만들지 않으므로, 그 계산 주소를 다른 문서가 사용해도 원래 URL과 관계를 유지합니다. 제목을 바꾸거나 별칭 주소를 추가할 때는 기존 충돌 검사를 적용합니다. 별칭은 줄마다 입력하며 쉼표가 포함된 이름도 보존하고, 입력에서 지운 별칭만 제거합니다. 문서나 별칭이 바뀌었으면 입력을 유지한 채 현재 저장본을 보여 주며, 비교 후 명시적으로 다시 저장해야 합니다. JavaScript 없는 기본 폼에서도 같은 버전 검사를 적용합니다.
- 직접 편집 미리보기: 현재 제목·본문·별칭 변경을 300ms 입력 지연 후 앱 서버에서 렌더링합니다. 새 문서의 자기 링크와 추가·삭제하는 별칭도 저장 시와 같은 주소 규칙으로 표시하며, 기존 문서의 주소는 유지합니다. 게시 화면과 같은 위키 문법·목차·문단 번호·별칭/미작성 링크·표·각주와 읽기 스타일을 사용합니다. 1024px 이상에서는 편집과 미리보기를 나란히, 작은 화면에서는 키보드로도 전환 가능한 탭으로 표시합니다. 화면 폭이 바뀌어도 미리보기의 링크·표와 입력란 초점을 유지하며, 사라지는 탭의 초점은 해당 편집 영역으로 이어집니다. 이 동작은 초안 수정과 최종 통합에도 적용합니다. 미리보기는 문서 저장·AI 검사·게시 승인을 하지 않으며 응답을 캐시하지 않습니다. 이전 요청을 취소하고 오래된 결과를 무시하며, 오류나 10초 시간 초과 시 입력을 유지하고 다시 시도할 수 있습니다. 미저장 변경과 새 문서 상태를 표시하고, 실제 저장 시 기존 버전/콘텐츠 검사를 그대로 적용합니다. JavaScript가 없으면 기본 작성·저장 폼을 유지합니다.
- 초안 입력 미리보기: 일반 초안과 최종 통합 본문에 같은 편집기를 제공합니다. 현재 제목·본문·별칭을 반영하고, **저장된 초안과 비교**는 별도 영역에서 확인합니다. 통합 미리보기는 원래 대상 제목·주소·별칭을 유지하며 적용 가능한 새 별칭만 포함하고, AI 원안과 편집 중인 최종 입력을 구분합니다. 두 편집기의 목차·각주 주소는 서로 다릅니다. 미리보기는 버전이나 검토 확인을 갱신하지 않으며 미저장 초안의 게시·통합 제한과 입력 복구를 유지합니다. 초안/통합 미리보기의 이미지는 기본적으로 링크로 표시합니다. **현재 미리보기의 이미지 표시**를 선택하면 이미지 주소로 요청을 보내 게시와 같은 이미지를 보여 줍니다. 선택은 각 편집기의 현재 입력에만 적용하며, 본문·제목·별칭이나 대상 초안/통합안이 바뀌면 해제됩니다. 불러오는 중이거나 실패한 이미지 수를 실제 로딩 결과로 표시하며 **이미지 다시 불러오기**로 재시도할 수 있습니다. 표시 선택은 문서를 저장하거나 검토 완료로 처리하지 않습니다.
- 직접 편집 임시 복구: JavaScript 사용 시 미저장 이동·새로고침을 안내합니다. 기본은 보관 안 함이며, 사용자가 체크한 민감 정보 없는 입력만 이 브라우저에 보관합니다. 제목·본문·별칭·편집자·요약과 원래 문서 ID/검토 버전을 함께 복구하며, 최신 버전을 자동 승인하지 않습니다. 화면/탭마다 복구본을 분리하고 복구 시 원본도 남깁니다. 마지막 보관 후 24시간이 지난 복구본은 편집 화면에 다시 들어오거나 복구 목록을 갱신할 때 삭제합니다. 체크 해제/문서 저장 성공은 현재 화면의 복구본만 삭제하며, 이전 복구본은 목록에서 개별 삭제합니다. 브라우저의 사이트 데이터 삭제로 전체 제거할 수도 있습니다. 휴지통 이동은 미저장 입력을 게시하지 않으므로 복구본을 유지합니다. 저장·삭제 응답을 기다리다 다른 화면으로 이동하면 이전 응답은 현재 화면의 입력이나 저장 상태를 바꾸지 않습니다. 이미 요청한 서버 작업은 계속 처리될 수 있으므로 원래 문서의 상태를 확인하세요. 이전 화면의 복구본은 검토할 수 있도록 남깁니다.
- 초안 임시 복구: 같은 보관 정책으로 제목·본문·별칭·검토자, 초안 ID/검토 버전, 통합안 ID·대상 선택·최종 본문·통합 검토자를 함께 복구합니다. 게시·삭제·통합 확인은 복구하지 않고 다시 선택해야 합니다. 이전 초안/통합안/대상 버전을 최신 승인으로 바꾸지 않으며, 오래된 초안은 저장본과 비교하고 명시적으로 저장해야 합니다. 초안 저장·통합안 생성 성공 후 다시 작성하는 입력에도 경고와 보관 선택이 적용됩니다. 삭제·게시된 초안의 복구본은 복사할 수 있지만 서버 초안을 재생성하지 않습니다. 초안 영구 삭제는 서버에서 되돌릴 수 없으며 브라우저의 미저장 복구본은 별도로 남습니다. 직접 편집 복구본과 초안 복구본은 다른 저장 영역을 사용합니다.
- 임시 보관 정책: 임시 복구 과정에서 서버·AI로 입력을 보내지 않습니다. 브라우저 저장소는 같은 기기의 이용자가 볼 수 있으므로 민감 자료에는 사용하지 마세요. 공통 로컬 보호 규칙에 걸린 입력은 보관하지 않으며, 의미 검사에서 거부된 입력은 현재 복구본과 같은 내용의 이전 복구본을 삭제합니다. 검사 거부 뒤 다른 입력 오류가 발생해도 임시 보관 차단을 풀지 않습니다. 초안과 최종 통합의 이미지 표시 선택도 보관하지 않습니다. 새로고침 후 입력을 복구해도 이미지는 기본 링크로 표시되며, 다시 선택해야 이미지 주소를 요청합니다. 현재 서비스에는 인증된 비공개 서버 임시 저장 정책/기능이 없어 민감 내용을 서버 초안으로 자동 전송하지 않습니다. 보호된 입력·저장 공간 부족·접근 차단은 화면의 입력과 이동 취소로 보존합니다. 사용자가 이동을 승인하거나 브라우저가 비정상 종료되면 복구를 보장하지 않습니다. JavaScript 없는 폼은 서버 저장/충돌 보호를 유지하며 브라우저 임시 복구·이동 경고의 미지원 안내를 표시합니다.
- 위키파이어: 모달 및 독립 페이지, DOCX/PDF/XLSX/PPTX 선택·드래그 업로드, 용량·형식 검사, 처리 상태와 오류 안내. 파일 하나에서 세부 작업·개별 점검 항목·조작 방법·판단 기준·고장 대응·용어를 독립적으로 설명할 수 있는 작은 지식 단위로 나눕니다(최대 32개). 예를 들어 펌프 점검 자료의 압력 확인·진동 기준·윤활유 보충·누유 대응·기록 작성은 각각 초안이 됩니다. 표의 머리글·단위·조건을 보존하고 문맥 없는 문장이나 셀 조각, 내용 없는 제목은 분리하지 않습니다. 단일 지식만 있으면 하나로 유지합니다. 전체 제목·범위를 먼저 정한 뒤 최대 8개씩, 최대 4개 요청으로 본문을 생성합니다. AI가 만든 제목·범위도 실제 텍스트로 콘텐츠 검사를 거치며, 어느 주제든 차단되면 모든 본문 생성과 초안 저장을 중단합니다. 이 경우 주제 검사 안내와 선택 파일을 유지하므로 원문 확인 후 다시 시도할 수 있습니다. 계획·전체 본문 생성은 합계 90초 제한을 공유하며 한 묶음이라도 실패하거나 제목·개수가 다르면 이번 업로드를 저장하지 않습니다. 관련 초안은 묶음이 달라도 연결하며 모든 초안을 한 트랜잭션으로 저장합니다. 결과에서 개별 수정하거나 목록에서 최대 8개씩 선택 게시할 수 있습니다. 더 큰 자료는 나누어 업로드하세요. API 키가 없으면 원문 기본 초안 하나와 AI 미연결 안내를 유지합니다.
- 초안: 본문을 바로 읽는 목록, 상태별 필터, 저장된 초안 미리보기와 초안 간 이동, 검사 사유, 수정 내용 저장 후 게시. 수정·삭제는 화면에서 검토한 버전이 DB 반영 시점에도 같아야 처리합니다. 충돌하면 입력을 유지하며 현재 저장본과 비교 후 명시적으로 다시 저장할 수 있습니다. 삭제는 저장된 미게시 초안의 영구 삭제 확인 항목을 선택해야 합니다. 본문은 200,000자까지 저장하며, 수정 시 기존 출처·부가 정보는 유지하고 오래된 AI 통합안만 초기화합니다.
